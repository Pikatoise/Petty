# Cat sprite assets

`cat-orange-white.png` is the shipped sprite atlas. It was **procedurally generated by
`src/Petty.Assets`** (a deterministic pixel renderer in this repository), not by an AI
image model — no image-generation tool was available in the build environment. Every
pixel is placed by code in `CatSpriteRenderer.cs` / `Animations.cs`, so the artwork is
reproducible, versionable and free of AI artefacts.

## Layout

- Atlas: `512x448`, 8 columns x 7 rows of `64x64` cells, row-major.
- Frames: 52 total, `cat-orange-white.json` describes each clip.
- Transparent background with a real alpha channel (`color type 6`, 8-bit RGBA).
- 7-colour palette, hard edges, no anti-aliasing (alpha is only 0 or 255).
- `groundRow: 52` — the row (including the 1px outline) that touches the ground.

| Clip | Frames | Cells | FPS | Loop |
|---|---:|---|---:|---|
| idle | 4 | 0-3 | 5 | yes |
| walk | 8 | 4-11 | 9 | yes |
| run | 8 | 12-19 | 14 | yes |
| eat | 6 | 20-25 | 7 | yes |
| sleep | 4 | 26-29 | 3 | yes |
| play | 8 | 30-37 | 11 | yes |
| pet | 4 | 38-41 | 4 | yes |
| tired | 4 | 42-45 | 4 | yes |
| exit | 6 | 46-51 | 9 | no |

The ball and the food bowl are **not** part of the atlas: the app draws both from their own
small PNGs, so the play and eat animations stay reusable.

| Prop | Size | Used as |
|---|---|---|
| `bowl-empty.png`, `bowl-25.png`, `bowl-50.png`, `bowl-75.png`, `bowl-full.png` | 24x24 | 72x72 px bowl, five food levels |
| `pour-0.png` � `pour-5.png` | 24x32 | click-through packet and falling food frames |
| `ball.png` | 16x16 | 48x48 px window while the cat plays |
| `hand.png` | 16x16 | 48x48 px window while petting |

Each bowl image supplies its own alpha hit mask as the food mound rises above the rim. Food amounts round up to the next quarter; zero alone is displayed empty.

## Regenerate

From the repository root:

```powershell
dotnet run --project src/Petty.Assets -c Release
```

or, with the helper script:

```powershell
./scripts/generate-assets.ps1
```

The catalog in `catalog.json` lists each variant's stable ID, breed, coat and seven RGB
palette colours in the order outline, coat, coat shadow, cream, cream shadow, pink, extra.
Add an entry and run the generator to create its atlas and metadata. The same animations
are shared by all entries. The saved state's `assetId` selects the atlas at runtime.
For hand-made art, set `source` to a directory under `assets/sprites` containing
`<id>.png` and `<id>.json`; its metadata must identify that ID and PNG. These source
files are preserved, copied unchanged and validated instead of being rendered.
The app never generates assets. The generator validates outputs and reuses valid files;
missing or invalid output is regenerated. Pass `--regenerate` to explicitly rebuild all assets
after changing the renderer or catalog.
Only atlases, metadata and shared props/icons are generated. To validate without writing:

```powershell
dotnet run --project src/Petty.Assets -c Release -- --verify
```

## Runtime variants

Bundled variants use `assets/sprites/<asset-id>.json` and the image named in that
metadata. Custom variants use the same convention in `<data-dir>/sprites/` and take
precedence over bundled variants with the same ID. IDs contain ASCII letters, digits and
hyphens; metadata `character` must match the filename ID. Optional metadata fields
`breedId`, `coatId` and `displayName` label the variant in the creation wizard.

Independent breed packs live in `assets/sprites/packs/<breed-id>/`, with three
`<asset-id>.png` / `<asset-id>.json` pairs. Use unique IDs; each JSON identifies its
same-named PNG and supplies `breedId`, `coatId`, `displayName`, `groundRow`, grid
dimensions and clip metadata. The app also discovers packs under
`<data-dir>/sprites/packs/`; custom IDs override bundled IDs. Duplicate IDs within one
root are rejected. Assets are copied into the published folder without registration.

All cells are 64×64, with 8-bit RGBA, binary alpha and transparent cell edges. The
required clips are idle, walk, run, eat, sleep, play, tired and exit. Clip ranges may
have different lengths; unused grid cells must be transparent. Authored packs may use
their own colors and markings. Validate a complete pack without modifying it:

```powershell
dotnet run --project src/Petty.Assets -c Release -- --verify --pack assets/sprites/packs/<breed-id>
```

## Validation

The generator re-decodes the written PNG and fails the run if any of these break:

- atlas size differs from `columns * frameWidth` / `rows * frameHeight`;
- any pixel is semi-transparent, or a generated catalog variant uses colors outside its palette;
- a frame is empty or touches the cell edge;
- a standing clip (`idle`, `walk`, `eat`, `tired`, `exit`) is not on `groundRow`;
- the walk loop jumps more than 2.5x a normal frame step;
- metadata is invalid (missing clip, overlapping clips, frames outside the grid).

Automated tests additionally verify the shipped metadata, the PNG header (real RGBA),
and frame counts (`tests/Petty.Tests/SpriteAssetFileTests.cs`).
